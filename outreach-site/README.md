# outreach.soniconsultancyservices.com

"Outreach Teardowns": a public teaching site on cold outbound, written in Het's voice from an
audit of 201 of Het's own outreach threads. Five articles, two free tools (a two-touch CRM and a
prospect scorer), three layers of email capture, and one understated line back to the studio.

**Status: built, not deployed.** Nothing here is live. No DNS, bucket or distribution exists yet;
see [Going live](#going-live-not-done) for the steps.

## Layout

```
outreach-site/
  content/            the words (Markdown with front matter)
    home.md
    articles/*.md     the-audit (flagship), what-failed, signal-based-targeting,
                      audit-first-method, the-quest-email
    tools/*.md        tools index, outreach-crm, prospect-scorer (copy around the apps)
  data/
    stats.json        EVERY number on the site: the audit figures, the 0-90 day window,
                      the send gap, and the scorer weights
    site.json         name, URLs, lead endpoint, download paths, CRM columns
  build.py            the generator (Python 3.9+, standard library only)
  templates/assets.py print/share-image templates used by `build.py --assets`
  scripts/serve.py    local server with production-like headers (clean URLs, 404, CSP)
  scripts/verify.mjs  browser checks (Playwright)
  public/             THE DEPLOY ARTIFACT: sync this folder, nothing else
```

Inside `public/`:

| Generated by `build.py` (never edit by hand) | Hand-written (edit directly) |
|---|---|
| every `*.html`, `sitemap.xml`, `robots.txt`, `llms.txt` | `assets/css/site.css` |
| with `--assets`: `downloads/*` (PDFs, CSV) and `assets/og/*.png` | `assets/js/*.js`, `assets/fonts/*`, `favicon.svg` |

## Editing

- **Words:** edit `content/**/*.md` and rebuild. Front matter holds the title, SEO title,
  description, kicker, dek and date. The body supports a small Markdown subset plus a few
  directives (`:::stats`, `:::timeline`, `:::check`, `:::more`, `:::steps`, `::::compare`
  with `:::annotated`), all documented at the top of the `Markdown` class in `build.py`.
- **Numbers:** edit `data/stats.json` only. Content refers to them as tokens (`{{threads}}`,
  `{{rejections}}`, `{{engaged.word}}`, `{{window_days}}`). The build refuses to run if a
  content file types one of the audit figures directly instead of using its token, so a
  corrected number can't be missed on some page. Changing `window_days` also needs one of the
  scorer's timing bands to end on the same day (the build tells you).
- **Scorer weights:** `data/stats.json` → `scorer`. The scorer page prints them in full, and
  the CRM's score chips use the same values.

## Building

```bash
python3 build.py              # regenerate pages into public/
python3 build.py --assets     # + playbook PDF, sequence PDF, CSV template, share images (needs Chrome)
python3 build.py --check      # exit 1 if public/ is stale against content/ + data/
python3 build.py --preview /tmp/outreach-preview   # relative links, forms in dry run
```

Every build also checks every internal link and `#anchor`, and checks that the studio CTA
appears exactly once (on `/tools/outreach-crm/`). It then prints word counts against the
brief's targets. `--assets` finds Chrome automatically on macOS, or set `CHROME_PATH`.

## Previewing and checking

```bash
python3 scripts/serve.py 5231                       # http://127.0.0.1:5231
BASE=http://127.0.0.1:5231 node scripts/verify.mjs  # needs Playwright; AXE_PATH=… adds axe
```

`verify.mjs` runs 288 checks. On every page, at 1366, 768, 390 and 375px, light and dark: no
horizontal scroll, no console errors or CSP violations under the production CSP, one h1,
valid JSON-LD, title and description length, OG tags, fonts loaded, footer byline present,
studio CTA only on the CRM page, and axe clean. It also tests the CRM cap (in the UI, through
CSV and JSON import, and in stored data), the scorer maths and share links, and all three
capture layers. It passed 288/288 before the first commit.

## Lead capture

All captures post to the **existing** lead endpoint the main site uses:
`https://9cjt6qwy71.execute-api.ap-south-1.amazonaws.com` (API Gateway → `scs-lead-mailer`
Lambda → DynamoDB `scs-leads` + email to the owner address). API Gateway already answers CORS
preflights with `access-control-allow-origin: *`, so no backend change is needed. This was
checked with an `OPTIONS` request only; no test lead was ever sent.

| Layer | Where | `kind` sent | Unlocks |
|---|---|---|---|
| Newsletter ("future teardowns") | footer of every page, end of every article | `newsletter` | – |
| Playbook PDF | home, end of every article, footer | `outreach_playbook` | `/downloads/cold-outreach-playbook.pdf` |
| CRM template + sequence | `/tools/outreach-crm/` | `outreach_crm_template` | the CSV template and the sequence PDF |
| CRM save/export | `/tools/outreach-crm/` toolbar | `outreach_crm_export` | save to browser, CSV/JSON export |

Payloads follow the Lambda's contract (`backend/lead/validate.mjs`): `email`, `kind`, `want`
(a plain-language line saying what they asked for), `consent`, `source_page` (full URL),
`referrer` (the landing referrer), `utm_*` when present, and the `website` honeypot. The
newsletter always sends `consent: true`. Gated downloads send `consent` only if the "also email
me new teardowns" box is ticked.

**Forms only send from `outreach.soniconsultancyservices.com`.** Everywhere else (localhost,
`file://`, previews, a bare CloudFront domain) they run dry: the payload goes to the console
and a toast says nothing was sent. To test the real pipeline on the CloudFront domain before
DNS exists, add `?leads=live` to the URL.

As on the main site's scoping guide, a network failure never blocks the download the visitor
asked for. A validation error from the Lambda, such as a disposable address, does block it
and is shown so they can fix the address.

## Going live (not done)

This mirrors the personal-site setup (`.deploy/RESOURCES.md` → "Personal site"). None of it has
been created.

1. **ACM certificate** in `us-east-1` for `outreach.soniconsultancyservices.com` (DNS validation).
2. **S3 bucket**, private, Block Public Access on.
3. **CloudFront** with OAC to the bucket. Alias `outreach.soniconsultancyservices.com`,
   default root object `index.html`, custom error responses 403/404 → `/404.html` (status 404).
4. **Viewer-request function** for clean URLs:
   ```js
   function handler(event) {
     var req = event.request, uri = req.uri;
     if (uri.endsWith('/')) { req.uri = uri + 'index.html'; return req; }
     var last = uri.substring(uri.lastIndexOf('/') + 1);
     if (last.indexOf('.') === -1) {
       var q = Object.keys(req.querystring).map(function (k) {
         var v = req.querystring[k].value; return v ? k + '=' + v : k; }).join('&');
       return { statusCode: 301, statusDescription: 'Moved Permanently',
                headers: { location: { value: uri + '/' + (q ? '?' + q : '') } } };
     }
     return req;
   }
   ```
5. **Response-headers policy.** `python3 scripts/serve.py` prints the exact CSP for the
   current build, because the inline theme script is allowed by hash. Today it is:
   ```
   default-src 'self'; script-src 'self' 'sha256-NgzTft2lBoonAPeJhRB2cNVd0Pwzpb4bFFjKtQqe+D0=';
   style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self';
   connect-src 'self' https://9cjt6qwy71.execute-api.ap-south-1.amazonaws.com;
   form-action 'self'; frame-ancestors 'none'; base-uri 'self'; object-src 'none'
   ```
   Plus `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`,
   `Referrer-Policy: strict-origin-when-cross-origin` and a `Permissions-Policy`. Adding
   analytics later means widening `script-src`, `img-src` and `connect-src`.
6. **DNS** at Hostinger: `CNAME outreach → <distribution>.cloudfront.net`.
7. **Upload** (only `public/`, never the whole folder):
   ```bash
   aws s3 sync outreach-site/public s3://<BUCKET> --delete --exclude "*.DS_Store"
   aws cloudfront create-invalidation --distribution-id <DIST_ID> --paths "/*"
   ```
8. **Verify**: `curl -sI "https://outreach.soniconsultancyservices.com/?cb=$RANDOM"`, then load
   pages in headless Chrome and look for CSP violations. Submit one real test lead of each kind
   and check the inbox.

`outreach-site/` is excluded from the main site's `aws s3 sync` (see CLAUDE.md). Keep it that way.
